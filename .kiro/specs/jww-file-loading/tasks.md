## Implementation Notes

- MFC オブジェクトタグの実定義は `wNullTag = 0x0000` / `wNewClassTag = 0xFFFF` / `wClassTag = 0x8000` / `wBigObjectTag = 0x7FFF`。クラス参照のインデックスは `tag & 0x7FFF`。MS TN002・MFC `arcobj.cpp`・LibreCAD jwwlib の 3 源で確認済み（タスク 2.1）
- `wBigObjectTag`（`0x7FFF`）は design.md の `JwwObjectTag` が 3 種のみのため未対応。後続 DWORD を消費しないが、未知クラスインデックスは jww-parser が解析エラーにするため無音では壊れない（タスク 2.1 レビュー指摘）
- 新規クラスタグ内のクラス名は `CString`（CP932）ではなく `WORD` スキーマ + `WORD` 長 + 生 ASCII（`CRuntimeClass::Store` の形式）
- MFC `CString` の長さ前置きは BYTE（`0xFF` 未満）→ WORD（`0xFFFF` 未満）→ DWORD のエスケープ連鎖。Unicode マーカ `0xFFFE` は JWW（ANSI/CP932）では出現しないため未対応
- MFC のカウントは WORD、`0xFFFF` がエスケープで DWORD が続く
- `JwwParseError` は依存方向を一方向に保つため `jww-archive-reader.ts` に定義。`jww-parser.ts` 側から re-export して design.md の公開インターフェースを維持する
- `TextDecoder("shift_jis")` は Vitest（Node v24.19.0）で正常動作を確認済み。research.md のリスク項目はクローズ
- ヘッダ前半のフィールド順は一次情報（jwwlib `jwdatafmt_en.txt` / `jwwdoc.cpp::ReadHeader()`）で確定: 署名 8B → `DWORD` バージョン → `CString` メモ → `DWORD` 図面サイズ → `DWORD` 書込レイヤグループ → 16 × { `DWORD` 状態, `DWORD` 書込レイヤ, `double` 縮尺, `DWORD` プロテクト, 16 × { `DWORD` 状態, `DWORD` プロテクト } }。1 グループ 148 バイト、ブロック計 2368 バイト（タスク 2.2）
- 実ファイル 3 件（`private/`、いずれも版 700）で走査位置を検証済み。状態ブロック直後にゼロ埋めのダミー `DWORD` 14 個が続くことを実測。縮尺は 16 グループとも 100.0、レイヤ状態 `0`（非表示）が実在する（タスク 2.3 の起点として利用可）
- バージョン検証は `version == 230 || version >= 300`（`jwwdoc.cpp` と同条件）。レイヤ／グループ状態は 0〜3 の範囲外を解析エラーにしてヘッダ誤読を早期検出する
- テストの合成ファイルビルダ `buildJwwFile()` は末尾の `rest?: number[]` が後続タスクの継ぎ足し口。2.3 はグループブロックと `rest` の間にレイヤ名フィールドを加算するだけでよい
- **タスク 2.3 の記述と design.md の「分岐点は Ver.3.00 / 3.51 / 4.20」は誤り。** ヘッダのバージョン分岐は 300（天空図・マークジャンプ 8 件・文字描画状態）と 420（拡張線色・拡張線種）の 2 か所のみ。「図形の線幅」`WORD` は図形基底クラス `CData` のフィールドで、`if (nOldVersionSave >= 351)` に囲まれている。タスク 2.4 では `CData` を 曲線属性 `DWORD` → 線種 `BYTE` → 線色 `WORD` → [≥351] 線幅 `WORD` → レイヤ `WORD` → グループ `WORD` → 属性フラグ `WORD` の順で読むこと（タスク 2.3 レビューの申し送り）
- ヘッダ後半の項目順は `jwwdoc.cpp::ReadHeader()` と 1 項目ずつ一致を確認済み。レイヤ名 256 件は **group-major**（`m_aStrLayName[グループ][レイヤ]` の二重ループ）、その直後にレイヤグループ名 16 件（タスク 2.3）
- 実ファイル 3 件のヘッダ終端と図形リスト先頭（いずれも版 700）: `共同研1階平面図` 14692 / 3485 件 / `CDataEnko`、`共同研階2･3平面図` 14645 / 6633 件 / `CDataMoji`、`共同研階4･屋上平面図` 14641 / 3712 件 / `CDataEnko`。±400 バイト走査で着地位置が一意であることも確認。**research.md の「版 700 は 420 以降の分岐で読める」という仮説は成立（タスク 5.2 で記録すること）**
- 残課題（非ブロッキング）: バージョン閾値 300 / 420 の境界値自体はテストで固定されていない（±1 しても 55 テストが通過する）。`buildJwwFile({ version: 300 })` と `{ version: 420 }` のヘッダ長ケースを足せば固定できる
- **MFC のロード配列インデックスはクラスとオブジェクトの両方を採番する。** 0 は null タグ予約、1 から連番。クラス登録で 1 枠、その直後のオブジェクト実体でもう 1 枠を消費するため、2 つ目のクラスはスロット 3 になる。`jwwdoc.cpp::Read()`・MS TN002・実ファイルのタグ列で確認済み（タスク 2.4）
- 図形基底 `CData` は 曲線属性 `DWORD` → 線種 `BYTE` → 線色 `WORD` → [≥351] 線幅 `WORD` → レイヤ `WORD` → レイヤグループ `WORD` → 属性フラグ `WORD`（≥351 で 15 バイト、未満で 13 バイト）。`CDataSen` は基底 + 始点 x,y・終点 x,y の 4 double、`CDataEnko` は基底 + 中心 x,y・半径・開始角・円弧角・傾き角・扁平率の 7 double + 全円フラグ `DWORD`（タスク 2.4）
- `jwdatafmt_en.txt` の `CDataSen` の記載は `m_start.x` が二度書かれたタイプミス。`jwwdoc.h` の `m_start.x, m_start.y, m_end.x, m_end.y` が正（タスク 2.4）
- タスク 2.4 時点の実ファイル走査到達点（2.5 のオラクル基準）: `共同研1階平面図` 120/3485 件（`CDataMoji` @21411 で停止）、`共同研階2･3平面図` 0/6633 件（@14647）、`共同研階4･屋上平面図` 219/3712 件（@26967）。**タスク 2.5 完了後は 3 件とも全要素を消費し切れるはず**。実ファイルの円弧は円弧角が厳密に ±π/2、扁平率が全件厳密に 1.0
- 残課題: `skippedCount` を観測するテストが存在しない（タスク 2.5 で追加すること）
